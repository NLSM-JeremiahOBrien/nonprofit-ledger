  <name>Task 1: Users table migration + argon2id password hashing</name>
  <files>server/db/migrations/0005_users.up.sql, server/db/migrations/0005_users.down.sql, server/auth/password.go, server/auth/password_test.go</files>
  <behavior>
    - HashPassword(pw) returns a self-describing PHC-style string ($argon2id$v=19$m=...,t=...,p=...$salt$hash); two calls with the same password produce different strings (random salt).
    - VerifyPassword(hash, pw) returns true for the correct password, false for an incorrect one, and false (not panic) for a malformed/unparseable hash string.
    - VerifyPassword uses subtle.ConstantTimeCompare for the final comparison (verify by code inspection is acceptable in addition to behavioral tests).
  </behavior>
  <action>
    Create migration 0005_users: `users` table with `id INTEGER PRIMARY KEY`, `username TEXT NOT NULL UNIQUE`, `password_hash TEXT NOT NULL`, `role TEXT NOT NULL CHECK (role IN ('staff_bookkeeper','admin','external_accountant'))`, `active INTEGER NOT NULL DEFAULT 1`, `must_change_password INTEGER NOT NULL DEFAULT 0`, `created_at TEXT NOT NULL DEFAULT (datetime('now'))`. This is a plain mutable table (like `accounting_periods`), NOT append-only — do not add immutability triggers here.

    Implement `server/auth/password.go` using `golang.org/x/crypto/argon2` (argon2id via `argon2.IDKey`) with baseline params `time=2, memory=19456 KiB, threads=1, keyLen=32`, a 16-byte `crypto/rand` salt, encoded as a PHC-style string embedding params+salt+hash so `VerifyPassword` is self-describing (no separately stored params). Run `go get golang.org/x/crypto/argon2` to add the dependency.

    Do NOT use `math/rand` anywhere. Do NOT use bcrypt.
  </action>
  <verify>
    <automated>go test ./server/auth/... -run TestPassword -x</automated>
  </verify>
  <done>Migration applies cleanly; TestPassword green; hash format round-trips through HashPassword/VerifyPassword.</done>
</task>

    First, spike-verify `github.com/alexedwards/scs/sqlite3store` against the project's `modernc.org/sqlite` driver: `go get github.com/alexedwards/scs/v2 github.com/alexedwards/scs/sqlite3store`, wire `sqlite3store.New(sqlDB)` against a real `*sql.DB` from `db.Open`, and confirm session read/write works. **If it fails** (driver incompatibility), fall back immediately: define the session store's schema (`token TEXT PRIMARY KEY, data BLOB NOT NULL, expiry REAL NOT NULL` + expiry index) as migration 0006_sessions instead of relying on the library's own table creation, and use that migration-backed table with `sqlite3store.New`.     Build `server/auth/session.go`: construct one package-level-configurable `*scs.SessionManager` (`sm.Store = sqlite3store.New(db)`, `sm.Lifetime = 12*time.Hour`, `sm.IdleTimeout = 2*time.Hour`, `sm.Cookie.Name = "ledger_session"`, `HttpOnly = true`, `SameSite = http.SameSiteLaxMode`, `Secure` configurable via `LEDGER_COOKIE_SECURE` env, default `true`, `Persist = true`).

    Build `server/users/users.go` with the minimal surface this plan needs: `type User struct { ID int64; Username string; PasswordHash string; Role string; Active bool; MustChangePassword bool }`, `ByUsername(db, username) (*User, error)`, `ByID(db, id) (*User, error)`. Full CRUD (Create/List/UpdateRole) is added in plan 02 — do not build it here, just the read path login needs.

    Build `server/api/auth.go`: `LoginHandler` reads `{username, password}` JSON, looks up the user via `users.ByUsername`, calls `auth.VerifyPassword`; on success calls `sm.RenewToken(ctx)` (prevent session fixation) then `sm.Put(ctx, "userID", user.ID)`, returns 200. On any failure (unknown user OR wrong password) returns the same generic 401 `{"error":"invalid credentials"}` — do not leak which field was wrong. `LogoutHandler` calls `sm.Destroy(ctx)`, returns 200.
