  <behavior>
    - TestSnapshot: given a live DB with committed writes (including some still only in the WAL, not checkpointed), `Snapshot` produces a new file via `VACUUM INTO` that contains all committed data — open the snapshot independently and confirm the latest write is present.
    - TestRotation: given N+2 snapshot files in a backup directory and a retain policy of N, `Rotate` deletes the 2 oldest by filename/mtime and keeps the N most recent; each `Snapshot`/`Rotate` run records a row in `backup_runs` with `status` ('success' or 'failed'), `file_path`, `size_bytes`, `started_at`/`finished_at`.
  </behavior>
  <action>
    Create migration 0008_backup_runs: mutable table (like `accounting_periods`, NOT append-only — health status is expected to be queried/summarized, not append-only-audited) with `id INTEGER PRIMARY KEY, started_at TEXT NOT NULL, finished_at TEXT, status TEXT NOT NULL, file_path TEXT, size_bytes INTEGER, error TEXT`.

    Implement `server/backup/backup.go`: `Snapshot(db *sql.DB, destPath string) error` runs `db.ExecContext(ctx, "VACUUM INTO ?", destPath)` — this is WAL-consistent and requires no manual checkpoint (do not hand-copy `.db`/`.db-wal` files, that pattern silently loses uncommitted-to-main WAL contents). `Rotate(dir string, keepN int) error` lists snapshot files in `dir`, sorts by name (timestamp-prefixed filenames, e.g. `ledger-20260808-153000.db`), deletes all but the `keepN` most recent. `RunScheduled(db *sql.DB, backupDir string, keepN int) error` wraps `Snapshot` + `Rotate`, times the run, and writes the resulting `backup_runs` row (success or failure with `error` populated) regardless of outcome.
  </action>
  <verify>
    <automated>go test ./server/backup/... -run TestSnapshot -x && go test ./server/backup/... -run TestRotation -x</automated>
  </verify>
  <done>Snapshot captures WAL-resident committed writes correctly; rotation prunes to exactly N retained files; every run is recorded in backup_runs with accurate status; TestSnapshot and TestRotation green.</done>
