Critical SQLite syntax constraint from research: `CREATE TRIGGER` accepts exactly one DML event per trigger (`BEFORE UPDATE` or `BEFORE DELETE`, never `BEFORE UPDATE OR DELETE`). Two separate triggers are required per protected table. This plan protects both `journal_entries` and `journal_lines` — that's 4 triggers total.

Money is stored as integer cents (`INTEGER`), never `REAL`. A journal line is a debit OR a credit, never both on the same row (enforced by CHECK).
</context>

```sql
CREATE TABLE journal_entries (
    id INTEGER PRIMARY KEY,
    entry_date TEXT NOT NULL,
    memo TEXT,
    posted_by INTEGER NOT NULL,
    posted_at TEXT NOT NULL,
    source TEXT NOT NULL DEFAULT 'manual',
    reverses_entry_id INTEGER REFERENCES journal_entries(id)
);

CREATE TABLE journal_lines (
    id INTEGER PRIMARY KEY,
    entry_id INTEGER NOT NULL REFERENCES journal_entries(id),
    account_id INTEGER NOT NULL REFERENCES accounts(id),
    fund_id INTEGER NOT NULL REFERENCES funds(id),
    functional_category TEXT
        CHECK (functional_category IN ('program','management_general','fundraising')),
    debit_amount INTEGER NOT NULL DEFAULT 0 CHECK (debit_amount >= 0),
    credit_amount INTEGER NOT NULL DEFAULT 0 CHECK (credit_amount >= 0),
    CHECK (NOT (debit_amount > 0 AND credit_amount > 0))
);

-- Paired BEFORE triggers per table (four total) — see 01-RESEARCH.md Pattern 2 for exact SQL.
```
