Anti-Pattern 3 (binding): fund/account balances must be derived via `SUM(debit_amount) - SUM(credit_amount)` queries against `journal_lines` — never a mutable stored `balance` column. If a cached projection table is added later for read performance, it must be clearly documented as rebuildable/verifiable against the journal, never authoritative. This plan does not need a projection table — direct derived queries are sufficient at this data scale.

Server stack per project STACK.md: Go stdlib `net/http` (or `go-chi/chi` if already pulled in) serving both the API and, in later phases, the embedded frontend build. This plan only needs a minimal server — no chi dependency required yet, stdlib mux is sufficient.
