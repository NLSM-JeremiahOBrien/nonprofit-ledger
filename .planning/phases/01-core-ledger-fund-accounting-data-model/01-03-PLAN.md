<objective>
Build `PostJournalEntry`, the single sanctioned entry point for creating new journal entries — the function every posting path (manual entry now, imports/reversals/bank-rec in later phases) must go through. It enforces three rules in one place: debits must equal credits, the entry date must not fall on/before a locked period, and expense-type account lines must carry a functional expense category.

Purpose: Per 01-RESEARCH.md, period lock and balance enforcement must live in the domain engine, not just UI validation — this is the choke point that guarantees every future caller (this phase's manual posting, and every later phase's automated posting) respects the same invariants.
Output: A period-lock schema and table, and a working `PostJournalEntry` that rejects unbalanced entries, entries in locked periods, and expense lines missing a functional category.
</objective>
